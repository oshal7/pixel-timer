The one rule that matters

Layers 40 and 50 are the only ones that sort dynamically. Everything else is painted in fixed order. Each floor object therefore needs an anchorY — the screen row where its base touches the floor. Chef in front when chef.anchorY > object.anchorY, behind otherwise.

Do not ask for transparent backgrounds

Image models fake transparency with checkerboard pixels baked into the image, which is unusable. Flat green keys out perfectly and your chef sheet already proves the workflow. Also forbid drop shadows onto the green — they turn into dark halos after keying.

Tileable textures are the exception

Floors and walls break two of the rules above, and the first run of Sheet 01 proved it. Two corrections:

  • No directional light on a flat texture. The preamble's "light from the upper left" makes the model add a centre bloom or corner shading. Tiled across a floor, that repeats as a grid of bright blobs. Textures need perfectly flat, uniform lighting — the preamble's lighting line must be explicitly overridden.
  • One texture per image, filling the canvas. Asked for in a grid, the model draws each texture as a little card with an outline, a bevelled edge and a drop shadow — which is exactly what makes it not tile. A texture that fills the whole canvas edge-to-edge has no border to draw.

Everything that is an object (rugs, furniture, props, icons) is fine in a grid — only seamless textures need the one-per-image treatment.

Verify before wiring

Run python3 tools/key_and_slice.py SHEET.png --out DIR --tile. It keys the green, slices every object, and scores each one: seam above 18 means visible grid lines when tiled, hotspot above 12 means repeating bright blobs. Anything flagged gets regenerated, not shipped.

04 Pipeline

From prompt to something the game actually loads. Steps 3–5 are scripted — send me the raw sheets and I'll run them.

  1. Lock a style anchor

    Generate Sheet 02 (walls & floor) first. Whichever result you like becomes the anchor image you attach to every later prompt — say "match the style, palette and lighting of the attached reference." This is what keeps ten sheets looking like one game.

  2. Generate one category per run

    Never ask for the whole kitchen at once. Models lose coherence past ~12 objects and start blending them. One sheet = one category = one prompt below.

  3. Key out the green

    Chroma-key #00FF00 to alpha with a tolerance pass and a 1 px despill to remove green fringing from edges.

  4. Slice to individual PNGs

    Connected-component detection finds each object's true bounding box — the same method that produced the current tileset — then trims and writes one PNG per asset.

  5. Emit a manifest

    Each sheet writes a JSON entry with id, file, footprint, anchorY, and layer. The game reads only the manifest, so swapping art later never touches code.

SHEET 10FX & overlays — rebuilt for keying2 runs · layer 70

The first run of this sheet came back as soft gaussian-blur clouds and one row that rendered as a glossy 3D fire emoji instead of pixel art. Both are the wrong tool for a chroma-key pipeline: a soft alpha falloff over flat green either keeps a green fringe or clips into an ugly hard edge — there is no clean key for a gradient. Real pixel-art FX (Stardew, Story of Seasons) never use blur; they fake softness with dithering — hard, opaque pixel clusters in a scatter pattern — which keys perfectly. Run these two prompts separately, and attach a real pixel-art VFX reference sheet if you have one.

HARD RULES — these must key cleanly off a flat green background:
