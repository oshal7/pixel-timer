When mirroring breaks

A flipped sprite reads wrong if anything on the character is asymmetric in a way that matters — a hand held out to one specific side, an object passed hand-to-hand. Chopping, stirring, presenting and the packet actions below are all front-facing at a fixed counter, so they're exempt from this rule entirely: generate them once, no mirroring involved.

"Right" and "Left" mean screen direction, not the character's own

Image models frequently flip this — asking for "the character's right side" is exactly the ambiguity that produces an inconsistent or mirrored result. Every prompt below is written as "toward the right edge of the frame" / "toward the left edge of the frame" instead. Keep that phrasing if you tweak anything — it's what actually locks the direction down.

Only 4 valid facings — never diagonal

If a batch comes back with the chef angled toward a corner (walking SW, SE, NW, NE instead of straight S, W, E, N), text warnings alone often aren't enough to override it — the model has a strong prior toward drawing stylized game-character portraits at a 3/4-turned angle, because that's what most of its training data of "cute pixel character" art looks like. Down/Up/Right/Left are the only 4 valid facings here, each exactly 90° apart, body square to the direction. The word "3/4" has been removed from the clamp entirely for this reason — see the workflow below for the fix that actually holds.

The fix: validate one frame before spending a whole batch

Don't generate a 6-frame sheet cold. For each new direction, first ask for a single static frame with the character reference attached — a small, cheap request. Confirm by eye that it's exactly cardinal (not angled toward a corner) before spending a full generation on it. Once you have one confirmed-correct frame for a direction, attach that frame alongside the character reference on the real 6-frame prompt and say "match this exact body orientation in every frame — the pose changes, the facing angle does not." A confirmed image is a far stronger anchor than another paragraph of text.

Your Character Reference image is already a perfect Down anchor

The single labelled reference you shared — chef standing straight-on, facing the camera dead-on, arms symmetric — is exactly the strict-cardinal Down pose this needs, with zero diagonal drift. Crop out the labels and use that exact image (not any of the diagonal batch results) as the attached reference for every Down-facing prompt. For Up and Right, don't ask the model to "turn" from this pose — ask it to rotate the whole rigid body 180° (Up) or 90° (Right) around a vertical axis, the way you'd spin a paper doll, landing on another strict cardinal pose, never a stop partway through the turn.

03 The character style clamp

Paste this at the top of every prompt in section 05, with the cropped reference image attached. It encodes the character design plus the technical rules that keep frames slotting into an animation without jitter.

CLAMPCharacter + technical rules — paste every timeattach reference crop
MATCH THE ATTACHED REFERENCE IMAGE(S) EXACTLY. Same character, same proportions, same palette, same outline weight — this is a style anchor, not inspiration.

CHARACTER: a cheerful middle-aged male chef. Tan skin, thick brown mustache, warm friendly expression. Tall white pleated chef's toque. Red bandana knotted at the neck. White double-breasted chef's jacket with a row of small buttons down the front. Red sash/belt at the waist. Grey trousers. Brown leather shoes.

BODY PROPORTIONS — chibi/super-deformed ratio, exactly 2 head-heights tall total: measure one head-height from the top of the skull to the chin. The ENTIRE REST OF THE BODY (neck, torso, arms, legs, feet, all combined) is exactly that same one head-height again. Total figure = 2 head-heights, split 1:1 between head and body. This is a much bigger head-to-body ratio than a realistic figure — check it against the attached reference before finalizing a frame. The tall chef's hat is extra height stacked ON TOP of this 2-head figure; it does not count toward the 2 head-heights and the body must not be shrunk to make room for it.

CAMERA (the viewing angle only — separate from which way the character is walking): a gentle elevated top-down camera, tilted just enough to see a little of the top of the hat and shoulders in every single frame no matter which way the character faces. Never a flat side-on silhouette with zero top visible, never a flat overhead view looking straight down. This camera angle is IDENTICAL across every direction sheet — only the character's pose changes, never the camera.

CHARACTER FACING — STRICT CARDINAL ONLY, NEVER DIAGONAL: picture a compass laid flat under the character. Down = due South (180°, straight toward the bottom edge of the frame). Up = due North (0°, straight toward the top edge). Right = due East (90°, straight toward the right edge). Left = due West (270°, straight toward the left edge, mirrored from Right). A prompt below will ask for exactly ONE of these four. The character's shoulders and hips are SQUARE to that exact compass heading — NEVER an intercardinal angle (NOT SW/135°, NOT SE/225°, NOT NW/45°, NOT NE/315°, and nothing in between). If you picture the character as a paper doll pinned at the spine, it is always resting flat at one of the 4 cardinal stops, never caught mid-turn between two of them. This is a strict 4-directional RPG-overworld sprite convention (the same convention Stardew Valley, Pokémon, and Zelda: A Link to the Past all use for their walking characters) — it is NOT a stylized 3/4-turned character portrait, which is a different, diagonal-facing art convention that does not belong anywhere in this sheet.

STYLE:
- 32-bit cozy pixel art, in the style of Stardew Valley character sprites.
- Bold, clean, consistent 2px dark outline around the ENTIRE silhouette and major interior seams (hat brim, jacket lapel, sash, shoe tops). This is what keys cleanly off the green — keep it identical weight on every frame.
- Crisp flat pixel shading, 3-4 tones per colour, no gradients wider than a couple of pixels, no blur, no soft anti-aliasing haze.
- Single light source from the upper-left, soft warm highlight, gentle cool shadow — matches the kitchen environment sheets.
- Character drawn at IDENTICAL scale in every image: same head size, same 2-head-height body, same hat height, same shoulder width. Do not zoom in or out between frames.

ANIMATION RULES (critical — this is what makes frames playable, not just a nice picture):
- All frames of one sequence are the SAME canvas size, and the character's feet stay glued to the SAME baseline row in every single frame. Only the pose changes — no vertical or horizontal drift frame to frame, or the animation will jitter in-game.
- Frames are laid out in a single horizontal row, left to right, evenly spaced, in the exact order they play back.
- Follow the frame-by-frame pose list given in each prompt EXACTLY, one listed pose per frame, in order. Do not default to a single pose repeated with only cosmetic differences (a blink, a tiny sway) when the prompt calls for a walk, climb or carry cycle — those need the leg and arm positions to actually change frame to frame, matching the listed pose for each numbered frame.

SHEET RULES:
- BACKGROUND MUST BE PURE FLAT CHROMA GREEN #00FF00, uniform edge to edge.
- NO drop shadow cast onto the green (contact shadow is a separate overlay, handled elsewhere).
- NO text, NO labels, NO numbers, NO watermarks, NO speech bubbles, NO motion lines.
